# Guidelines for Cyber Security Roles

This guideline covers governance roles required to operate cyber security in an
organisation: the Chief Information Security Officer (CISO) or equivalent, the system
owner, the cyber security personnel, and the relationships between them.

## In plain English

Name the people accountable for cyber security at the organisation, at the system, and at
the technical-operations layer. Document the relationships between them. Provide a way
for issues to escalate and decisions to be made.

## Why it exists

Cyber security incidents fail-open when nobody is named accountable. Assessors expect to
see a clear chain from "who decided this system is acceptable" to "who watches it day to
day".

## Key topics

- Appointment of a CISO or equivalent senior accountable executive.
- Appointment of system owners for each system.
- Identification of cyber security personnel and their training.
- Relationship to the agency Chief Security Officer (CSO) where the agency has one (the
  PSPF expects the CSO role).

## Where to look

- Org-chart documentation.
- Charter or role descriptions for CISO, CSO, system owner.
- Delegation registers showing who can accept residual cyber risk.
- Position descriptions for cyber security engineers, analysts and developers
  including security responsibilities.

## Common evidence

- Letter of appointment for the CISO.
- System owner register.
- Cyber security personnel training records.
- Risk acceptance records signed by the named accountable executive.

## Common pitfalls

- "CISO by committee" with no single named accountable individual.
- System owner role assigned to a delivery manager who has no authority to actually
  accept or reject residual risk.
- Cyber security personnel without security-specific position descriptions or training.
