# Guidelines for Evaluated Products

This guideline covers the use of products that have been evaluated against recognised
schemes such as Common Criteria and the Australasian Information Security Evaluation
Program (AISEP).

## In plain English

Some product categories must use evaluated products at certain classifications. Check the
ACSC's Evaluated Products List before buying.

## Why it exists

Evaluated products provide assurance over key cryptographic and security functions. At
PROTECTED, some product categories carry a hard requirement to use an evaluated product.

## Key topics

- Evaluated Products List (EPL) maintained by the ACSC.
- Common Criteria evaluations and protection profiles.
- High Assurance products (for higher classifications, outside this pack's scope).
- Configuration requirements specific to the evaluated configuration.

## Where to look

- Procurement records showing EPL check.
- Product configuration documents proving the evaluated configuration is in use (the
  evaluated configuration is often narrower than the product's default).
- Vendor letters confirming evaluation status.

## Common evidence

- Letter or EPL listing for each in-scope product.
- Configuration baseline matching the evaluated configuration.
- Annual re-check of EPL status (products can fall off the list).

## Common pitfalls

- Buying the product but running it in a non-evaluated configuration.
- Treating SOC 2 attestation as evaluation. Different schemes.
- Stale EPL references where the product has been removed.
- Using a different model in the same product family that was not evaluated.

## Cross-references
